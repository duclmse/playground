# M8 — Debugging + profiling (zero-overhead-when-disabled)

**Goal**: give fastlua developers real introspection tools - step-debugging
and time-profiling - without weakening the "beats LuaJIT" promise for
anyone who isn't using them. Not in `faster_lua.md` itself; a standing
requirement the user added mid-M7 session.

**Hard constraint**: `fastlua run <file.fl>` (no debug/profile flags) must
not regress. Enforced structurally, not just tested: `interp::Runtime`/
`tier::Engine` are generic over `H: interp::Hooks` (default `()`), and
`fastlua run`'s only code path (no flags) instantiates `Engine<()>` -
`()`'s `Hooks` impl has empty method bodies that inline away entirely, a
genuinely different compiled function from `Engine<TimingHooks>`
(`--profile-time`) or `Engine<DebugHooks>` (`debug`), not a runtime-checked
branch. Verified empirically too: `benchmarks/RESULTS.md`'s M8 section
compares the pre-M8 binary against the post-M8 one on 4 benchmark shapes
(call-heavy, recursion-heavy, array-heavy, alloc-heavy) - all within
measurement noise, no regression in either direction.

**Depends on**: M6/M7 (the tiered `Runtime`/`Engine` this hooks into).

- [x] **Profiling** (`fastlua run --profile-time <out>`, `profile.rs`):
      `TimingHooks` wraps every `Runtime::call` with `Instant::now()`,
      reporting inclusive wall time (including callees - a real, honestly-
      scoped simplification, not self/exclusive time) and call count per
      function, sorted by time descending. **Real, documented limitation**:
      only sees calls routed through `Runtime::call` - once a function is
      promoted to native and calls itself (or another native function)
      directly via Cranelift's own call instruction, those calls are
      invisible to the profiler entirely (confirmed empirically: `fib.fl`
      showed 221 calls to `fib` at default thresholds, once promoted, vs.
      the true 7,049,155 with promotion disabled). This is the honest cost
      of a call-boundary-hook design that adds no overhead to native code
      itself - instrumenting native call sites too would mean either
      compiling two versions of every function or a runtime branch inside
      JIT'd code, both real costs the zero-overhead constraint rules out.
- [x] **Debugging** (`fastlua debug <file.fl>`, `debug.rs`): a REPL
      debugger via the same `Hooks` mechanism - `break <fn>`/`continue`/
      `step`/`backtrace`/`quit`, pausing at function-call boundaries.
      Works uniformly across every execution tier (interpreted,
      promoted-native) for the same reason profiling does - the hook wraps
      the call boundary itself, before tier dispatch, so it doesn't need
      to force tier-0-only execution. **Scoped down, documented**: call-
      boundary granularity only, not per-source-line - real line-level
      breakpoints would need source line numbers threaded through the
      typed AST into bytecode, complicated by M2/M3's optimizer passes
      reordering/rewriting statements after type-checking (a substantially
      larger undertaking, not attempted this pass). `args`/return values
      print as raw `u64` bits, not type-formatted (no live type info at a
      call boundary - `bytecode.rs::BcFunction` doesn't carry per-register
      types, and adding them would still not help since the debugger has
      no access to *mid-function* register state, only call-boundary
      values) - honest, not false precision.

**Explicitly out of scope**: mid-function/per-line stepping and variable
inspection (needs the line-number-threading work above); a full DAP
server matching `crates/dap-server`'s existing pattern for the Lua VM
(that crate is ~760 lines for a VM that already had native debug hooks
built in - a comparable investment for fastlua is real, valid future work,
not attempted here given the size of everything else this session already
covered); allocation/object-shape profiling (§23's fuller PGO vision,
already noted as open in M7).

**Files**: `interp.rs` (`Hooks` trait, `Runtime<'a, H: Hooks = ()>`),
`tier.rs` (`Engine<H: interp::Hooks = ()>`, `hooks()`/`name_of` accessors),
`profile.rs` (new - `TimingHooks`), `debug.rs` (new - `DebugHooks`),
`main.rs` (`--profile-time` flag, `debug` subcommand),
`tests/fixtures/debug_calls.fl`.
